# 소통 방식

- 답은 한국어로. 사용자는 개발 초보자라 단계마다 무엇을 왜 하는지 짧게 설명한다.
- **계획을 먼저 보여주고, 사용자가 확인한 뒤에 코드를 작성한다.** (작은 수정 요청은 바로 해도 된다)
- 서버에서 할 일은 복사해 붙일 수 있는 명령으로 한 줄씩 안내한다.
- 결과는 있는 그대로 말한다: 테스트 실패·확인 못 한 것·추측한 것은 그렇다고 밝힌다.
- 사용자가 도구 실행을 거절하거나 중간에 멈춰도 파일이 이미 바뀌었을 수 있다. 반드시 `git status` 로 확인하고 정직하게 알린다.
- 주황색은 쓰지 않는다 (예외: 주문 상태 배지 '작업 중' — `design.md` 참고).
- 속도 개선은 "나중에 천천히" 하기로 했다. 먼저 꺼내지 않는다.
