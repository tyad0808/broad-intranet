# 기획서: 주문 현황판 (인트라넷 5단계)

> 브로애드 인트라넷의 첫 화면을 "주문 현황판"으로 만든다.
> 모든 주문(스마트스토어 자동 수집 + 전화·매장·카톡 직접 등록)을 한 화면에 모으고,
> 누가 무엇을 언제까지 하는지 한눈에 보이게 한다.

---

## 1. 왜 만드나

| 지금 문제 | 현황판이 생기면 |
|---|---|
| "그거 누가 하고 있어?", "언제 나가?" 를 매번 물어본다 | 카드에 담당자·납기가 보인다 |
| 스마트스토어 주문과 전화·매장 주문이 따로 논다 | 모두 같은 판에 카드로 모인다 |
| 납기 지난 주문을 늦게 알아챈다 | 빨간색으로 표시되고 맨 위 요약에 건수가 뜬다 |
| 담당자 없는 주문이 방치된다 | "미배정" 건수가 보인다 |
| 예전 주문("작년 그 현수막")을 찾기 어렵다 | 고객명·전화번호로 완료 주문까지 검색 |

**원칙: 직원이 정신없지 않게.** 화면은 하나(현황판), 직원은 기본으로 자기 일만 보는 탭을 쓸 수 있게, 기능은 꼭 필요한 것만.

---

## 2. 범위

### 이번에 만드는 것
1. 현황판 화면 (로그인 후 첫 화면 `/`)
2. 주문 직접 등록 (전화·매장·카톡·기타)
3. 주문 상세 화면: 단계 이동, 담당자·납기·급·작업 메모, 완료 처리, 변경 기록
4. 검색 (완료 주문 포함)

### 이번에 안 하는 것 (나중 단계)
- 금액·입금·세금계산서 (→ 정산 단계)
- 송장번호·고객 발송 문자 (→ 발송 처리 단계)
- 거래처(단골) 관리 (→ 거래처 단계)
- 카드 끌어다 놓기(드래그) — 실수가 많아 버튼 방식으로
- 시안 컨펌 연동은 시안 기능을 켤 때 상세 화면에 [시안 보내기] 버튼만 추가

## 3. 화면

### 3-1. 현황판 (`/`, 로그인한 승인 직원만)

```
┌─────────────────────────────────────────────────────────────────────┐
│ 브로애드 인트라넷                              관리자  홍길동  로그아웃 │
├─────────────────────────────────────────────────────────────────────┤
│ [오늘 발송 5] [내일 발송 3] [납기 지남 1(빨강)] [미배정 2]             │ ← 요약 칸 (누르면 필터)
│ (전체 주문) (내 작업 (4)) (완료)  [🔍 고객명·상품·전화번호   ] [+ 주문 등록] │
├──────────┬──────────┬──────────┬──────────┬──────────┬──────────┤
│ 발주   2 │ 발주확인 1│ 디자인작업3│ 컨펌   2 │ 제작   2 │ 발송   2 │ ← 작업 단계 = 칸
│┌────────┐│┌────────┐│┌────────┐│          │          │          │
││현수막   │││폼보드 A1│││[급]입간판││          │          │          │
││5000×900│││전화 카페 │││매장 정형 ││          │          │          │
││스토어 ㈜한││박출력    │││김디자    ││          │          │          │
││담당자없음││ 납기 내일││ 납기 내일││          │          │          │
│└────────┘│└────────┘│└────────┘│          │          │          │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
```

- **칸** = 관리자 메뉴의 "작업 단계" (활성 단계만, 정한 순서대로). 관리자가 단계 이름·순서를 바꾸면 칸도 바뀐다.
  - 숨긴 단계에 있거나 단계가 비어 있는 카드는 맨 앞 **"단계 없음"** 칸에 모은다 (카드가 사라지지 않게).
- **카드에 보이는 것**
  - 상품명, 규격·옵션
  - 접수 경로 꼬리표: 스토어(초록) / 전화(파랑) / 매장(주황) / 카톡(노랑) / 기타
  - 고객명 · 수량
  - 담당자 (없으면 빨간 "담당자 없음")
  - 납기: 오늘 / 내일 / 10/24 형식
  - [급] 빨간 꼬리표
  - 네이버에서 취소·반품된 주문이면 빨간 "취소" 표시
- **카드 왼쪽 띠 색**: 빨강 = 납기 지남, 주황 = 오늘·내일 납기, 회색 = 여유
- **칸 안 정렬**: 급한 것 → 납기 빠른 것 → 납기 없는 것 → 먼저 들어온 것
- **카드를 누르면** 주문 상세 화면으로

#### 요약 칸
| 칸 | 조건 (완료 전 주문 중) |
|---|---|
| 오늘 발송 | 납기 = 오늘 |
| 내일 발송 | 납기 = 내일 |
| 납기 지남 | 납기 < 오늘 (1건 이상이면 빨간 칸) |
| 미배정 | 담당자 없음 |

- 누르면 그 주문만 보이게 거르고, 다시 누르면 해제. 거르는 중에는 "○○만 보는 중 · 전체 보기" 안내.
- "내 작업" 탭에서는 요약도 내 주문 기준.
- **날짜는 한국 시간 기준** (DB 는 UTC 로 저장하므로 주의).

#### 탭
- **전체 주문**: 완료 전 모든 주문
- **내 작업 (N)**: 나에게 배정된 완료 전 주문만. 탭에 건수 표시
- **완료**: 완료 처리한 주문, 최근 것부터 100건

#### 검색
- 상품명, 옵션, 고객명, 받는 분, 메모, 주문번호, 주소, 전화번호에서 찾는다.
- 전화번호는 하이픈 없이 쳐도 찾는다 (`55557777` → `010-5555-7777`).
- 띄어쓰기로 여러 단어를 넣으면 모두 들어간 주문 (예: `학원 배너`).
- **완료한 주문까지** 찾는다. 결과는 카드 목록, 카드에 현재 단계 또는 "완료" 표시. 최대 100건.
- `%`, `_` 같은 글자도 글자 그대로 찾는다 (SQL LIKE 이스케이프).

#### 휴대폰
- 칸을 세로로 쌓고, **빈 칸은 숨긴다**.
- 요약 칸은 2×2, 탭은 가로로 꽉 차게.
- 가로 스크롤이 생기지 않게.
- PC 에서는 단계가 많아지면 현황판 안에서만 가로 스크롤.

### 3-2. 주문 등록 (`/orders/new`)
전화·매장·카톡으로 받은 주문을 직원이 넣는다. (스마트스토어 주문은 자동 수집되므로 넣지 않음)

| 칸 | 필수 | 비고 |
|---|---|---|
| 접수 경로 | ✔ | 전화 / 매장 / 카톡 / 기타 (라디오, 기본 전화) |
| 상품 | ✔ | 200자 |
| 규격·옵션 | | 예: 5000×900 / 타폴린 |
| 수량 | | 기본 1, 1~99999 |
| 고객명(업체명) | ✔ | |
| 전화번호 | | |
| 주소 | | 배송할 때 |
| 담당자 | | 승인된 직원 목록 (직무 함께 표시) |
| 납기 | | 날짜 선택 |
| 급한 주문 | | 체크 |
| 작업 메모 | | 2000자. 예: 타폴린 / 아일렛 4구 / 퀵 배송 |

- 등록하면 "새 주문 단계"(설정 `stage_new`, 기본 '발주') 칸에 들어간다.
- 입력이 틀리면 저장하지 않고 안내 문구 (예: "상품을 입력하세요", "납기 날짜가 올바르지 않습니다").

### 3-3. 주문 상세 (`/orders/:id`)

```
← 현황판
[급] 입간판 시트 교체   (디자인작업)
┌ 단계 ──────────────────────────────────┐
│ [발주][발주확인][■디자인작업][컨펌][제작][발송] │ ← 아무 단계나 바로 이동
│ [        다음 단계: 컨펌 →         ]       │ ← 큰 버튼 (마지막 단계면 ✔ 완료 처리)
└────────────────────────────────────────┘
┌ 주문 정보 ─────────────────────────────┐
│ 접수  매장 · 2026-10-20 09:12             │
│ 고객  정형외과의원                         │
│ 전화  031-555-1234 (누르면 전화 걸기)       │
└────────────────────────────────────────┘
┌ 작업 ──────────────────────────────────┐
│ 담당자 [김디자 ▼]   납기 [2026-10-21]       │
│ ☑ 급한 주문                                │
│ 작업 메모 [실측 600×1800, 화요일 직접 수령]   │
│ [저장]                                    │
└────────────────────────────────────────┘
┌ 기록 ──────────────────────────────────┐
│ 10-20 10:02 · 김디자  단계: 발주 → 디자인작업 │
│ 10-20 09:12 · 최CS   주문 등록 (매장)        │
└────────────────────────────────────────┘
```

- **단계 이동**: 단계 버튼 줄 + "다음 단계" 큰 버튼. 이동할 단계 번호를 보내므로 두 번 눌러도 결과가 같다 (같은 단계면 기록도 안 남김).
- **완료 처리**: 마지막 단계에서 [✔ 완료 처리] (확인창). 현황판에서 빠지고 [완료] 탭으로.
  - 완료한 주문은 단계 이동 불가, [다시 열기] 버튼만.
- **직접 등록한 주문**은 상품·고객 칸도 고칠 수 있다.
- **스마트스토어 주문**은 상품·고객 칸을 고칠 수 없다 (주문 수집 때 네이버 값으로 덮어쓰기 때문). 주문번호·채널 상태를 보여주고, 담당자·납기·급·메모만 고친다.
- 네이버에서 취소·반품되면 상단에 "취소된 주문입니다. 작업하지 마세요." 빨간 안내.
- **기록**: 바뀐 것만 남긴다. 아무것도 안 바꾸고 저장하면 "바뀐 내용이 없습니다", 기록 안 늘어남.

## 4. 데이터

기존 `orders` 표에 이미 있는 칸: `stage_id`, `assignee_id`, `due_date`, `memo` (사내 칸, 주문 수집이 건드리지 않음)

### 4-1. `orders` 에 추가할 칸 (예전 DB 에는 없을 때만 `ALTER TABLE ADD COLUMN`)
| 칸 | 형식 | 뜻 |
|---|---|---|
| `urgent` | INTEGER NOT NULL DEFAULT 0 | 1 이면 [급] |
| `done_at` | TEXT | 완료 처리 시각. 값이 있으면 현황판에서 빠짐 |
| `created_by` | INTEGER → users | 직접 등록한 직원 |

인덱스: `done_at`

### 4-2. 직접 등록 주문
- `channel`: `phone` / `walkin` / `kakao` / `etc` (스마트스토어는 `smartstore`)
- `channel_order_id`, `channel_item_id`: `M-` + 무작위 10자리 (UNIQUE 제약 충족용)
- `receiver_name` 은 고객명과 같게, `paid_at` 은 등록 시각

### 4-3. 새 표 `order_events` (변경 기록)
| 칸 | 뜻 |
|---|---|
| id | |
| order_id → orders | |
| user_id → users | 누가 (자동 처리면 비움 → "자동") |

인덱스: `order_id`

## 5. 주소 정리

| 방식 | 주소 | 하는 일 |
|---|---|---|
| GET | `/` | 현황판 (`?view=mine` 내 작업, `?view=done` 완료, `?f=today/tomorrow/late/unassigned` 요약 필터, `?q=` 검색) |
| GET | `/orders/new` | 주문 등록 화면 |
| POST | `/orders` | 주문 등록 |
| GET | `/orders/:id` | 주문 상세 |
| POST | `/orders/:id` | 담당자·납기·급·메모(+직접 주문은 상품·고객) 저장 |
| POST | `/orders/:id/stage` | 단계 이동 (`stage_id`) |
| POST | `/orders/:id/done` | 완료 처리 |
| POST | `/orders/:id/reopen` | 다시 열기 |

- 모두 로그인 + 승인된 직원만 (`requireActive`). 로그인 안 했으면 `/login`, 승인 대기면 `/pending`.
- 모든 POST 는 기존 CSRF 토큰 검사.
- 기존 홈(`home.ejs`)의 "주문 목록은 5단계에서…" 안내는 현황판으로 대체. 관리자에게 보이던 "승인 대기 N건" 안내는 현황판 위에 그대로.
- 관리자 메뉴 → 주문 수집 탭의 "(주문 목록 화면은 5단계)" 문구를 "작업은 현황판에서" 로.

## 6. 권한 (기본안)

- 단계 이동, 담당자 지정, 납기·메모 수정, 완료 처리: **승인된 직원 모두**
  - 대신 변경 기록에 누가 했는지 남는다.
- 나중에 필요하면: 담당자 지정·완료 처리를 관리자만 / 다른 사람 담당 주문 수정 막기 등을 설정으로 추가.

## 7. 주의할 점

- **주문 수집과 충돌 금지**: 수집기(`collector.js`)는 채널 칸만 고친다. `urgent`, `done_at`, 담당자, 납기, 메모는 수집해도 그대로여야 한다.
- **화면에 나오는 글은 모두 이스케이프** (고객이 상품명·메모에 HTML 을 넣어도 실행되지 않게, EJS `<%= %>`).
- **CSP**: `script-src 'self'` 이므로 화면 스크립트는 `public/` 의 별도 파일로 (완료 처리 확인창은 기존 `confirm.js` 재사용).
- **날짜 비교는 한국 날짜** (`YYYY-MM-DD`, UTC+9).
- **node:sqlite** 에서 이름 붙인 값(`:today`)을 쓰는 쿼리에 안 쓰는 값이 넘어가면 오류 → `setAllowUnknownNamedParameters(true)` 또는 쿼리별로 값을 맞춰 넘긴다.

## 8. 테스트 (node:test, 기존 helpers 사용)

1. 로그인 안 하면 `/`, `/orders/new`, `/orders/1` 이 `/login` 으로, 승인 대기는 `/pending` 으로
2. 전화 주문 등록 → '발주' 칸에 카드, 급·납기 내일 표시, 기록 `주문 등록 (전화)`, `담당자: ○○`
3. 필수 칸 빔 / 틀린 날짜 / 엉뚱한 접수 경로 → 저장 안 되고 안내
4. 단계 이동 → 같은 단계 두 번 눌러도 기록 1번 → 마지막 단계에서 완료 → 현황판에서 빠지고 완료 탭에 → 완료 주문은 단계 이동 안 됨 → 다시 열기
5. 담당자·납기·메모 수정 시 바뀐 것만 기록, 그대로 저장하면 기록 안 늘어남, 내 작업 탭에는 내 담당만
6. 요약 칸 건수(오늘·내일·지남·미배정)와 필터
7. 검색: 하이픈 없는 전화번호, 여러 단어, 완료 주문 포함, `%_` 글자 그대로, 결과 없음 안내
8. 스마트스토어 주문: 상품 칸 수정 불가, 사내 칸만 수정, 다시 수집해도 사내 칸 유지, 취소되면 취소 표시
9. 숨긴 단계의 카드는 '단계 없음' 칸에
10. 상품명·고객명·메모의 HTML 이 글자로만 보임
11. 예전 DB 에 새 칸이 자동 추가되고 기존 주문 유지
